## 一、目标与真实起点

目标是把独立目录模块接到实际 Qt 软件中：选择搜索范围 → 后台建立目录 → 在“探索”中找到真实文件 → 原位置预览／打开 → 后台跟踪变化。保留现有资料库、正文检索、收藏和完整智答能力，并实施用户已确定的极简界面调整。

当前不是从零开始，也不是已有完整全盘搜索：

- `search_app/discovery/` 经 Codex 修订后为 **0.2.0 / catalog schema 2**，不是初交付的 schema 1。以 `docs/discovery_prework/REVIEW.md`、`review-manifest.json` 和实际源码为起点。
- 当前全量回归 **289 项通过、无跳过**，其中 discovery 74 项。原 40 项通过不能代替此次基线。
- 现有能力：流式目录枚举、独立 catalog、字面查询、事件去重与事务游标、目录通知、错误／离线保留、128 位 ID、长路径等。
- `DiscoveryService.scan_source` 仍走通用初始扫描；`bounded_usn_enum` 只是有界实验。尚无生产级原生完整建库和应用生命周期调度。
- 当前机器 F: 可读 USN，修订后有界枚举 1,000 条、992 条路径已解析、8 条未解析；C:/D:/E: 当前权限下不可读。必须重新探测，不把这些历史值当成当次结果。
- Qt 主窗口尚未接 discovery。“搜索、资料库、镜仔智答、收藏”四个侧栏入口仍在；“探索／智答”、文字侧栏、框内放大镜等提案尚未实施。
- `index.db` 是原内容库，`catalog.db` 是新文件目录库。目录存在不代表正文、OCR 或画面已经分析。

先读：`docs/NATIVE_DISCOVERY_PLAN.md`、`docs/discovery_prework/REVIEW.md`、`docs/SEARCH_AND_QA_NEXT_PLAN.md`、`docs/QT_MINIMAL_UI.md`、`docs/QT_PARITY_REVIEW.md`、`docs/LEGACY_USER_GUIDE.txt`。

## 三、实施顺序与任务

按 A → B → C → D → E 推进；F 是必须交付的后续设计与能力核对，实际多模态实现另设验收。先完成一条真实可用链路，再扩展，不把所有工作停在接口和效果图。

### A. 应用级后台调度与范围管理（必须）

1. 在 Qt 与 discovery 之间建立独立控制层，复用现有 `Jobs` 或职责清楚的后台工作器。UI 主线程不探测卷、不扫盘、不做大查询／正文解析，不等待 observer.join 或长事务。
2. 增加“搜索范围”原生 Qt 管理面板。可列出本机可探测卷，添加指定目录；支持选中／取消来源、开始建立目录、停止／继续、更新、移除索引范围、查看失败原因。
3. 全电脑是多个实际已选择来源的集合，不是把一次 `os.walk('C:\\')` 包装成“全电脑”。固定盘、可移动盘、网络位置分别显示能力；离线／无权限／重解析点不递归等限制可查。
4. 来源有稳定身份；同一路径重复添加复用来源。重叠根目录不能造成同一真实路径在结果中重复显示；实现合并／去重规则并说明，保留不同硬链接路径与不同副本。
5. 首次启动不擅自启动全电脑正文分析。范围在隔离配置中持久化；再次启动恢复已选范围、目录记录和任务状态，未完成来源可继续／补扫。
6. 每个来源的扫描／同步串行，跨来源并发有明确上限。重复点击开始、定时器和手动更新不能同时对同一来源执行扫描与补扫；补扫合并、防抖，出错不能无限紧循环。
7. 持续更新：USN 可用时定时读取提交游标后的变更；通用通道使用持久目录通知和必要补扫。现有 `scan_source` 中的临时 watcher 不等于扫描结束后已持续监听；必须补齐交接空窗和生命周期。
8. 离线、日志失效、通知溢出、进程异常后恢复需要明确状态。失败或取消保留旧索引；离线结果有标记。失败的来源不阻塞其他来源和已有搜索。
9. 窗口最小化／隐藏时后台任务继续；真正退出时可取消、释放句柄／观察线程并正确收尾。退出不在 UI 线程长时间阻塞，不留下重复后台进程。
10. 覆盖信息至少有：所选位置、目录已发现数量、当前通道、进行中／完成／待补扫／离线、错误数、更新时间。正文／图像进度独立，未实现的不能写“完成”。

交付：控制层、范围面板、持久设置、自动／手动更新与取消、重启恢复的可运行流程和测试。

### B. 完整原生 NTFS 初始建库（必须实现，权限不足可真实回退）

1. 在现有只读 FSCTL 封装基础上增加完整枚举器。区分“有界探测”和“完整建立目录”；达到记录／时间限制必须标记未完成，不能当作扫描完成后清旧记录。
2. 记录初始 Journal ID 与 USN，分批枚举并构建父子关系、路径和对象；结束回放扫描期间的变更。日志换代／过期或未知记录不能推进游标冒充一致。
3. 设计有界内存与磁盘暂存方案，避免把整盘所有记录、完整路径和多份 FRN 字典同时放进内存。根 ID、父目录晚到、缺父路径、循环／坏链、重解析点与排除子树都要处理。
4. 原生枚举对硬链接多路径的覆盖必须实证。必要时补枚举或回退通用通道；不能因为 FRN 相同只保留一个文件名，也不能把不完整结果报完整。
5. 无法从原生记录获得的 size／mtime 不得伪造为 0。采用可靠补充元数据或明确未知值，排序和 UI 能处理未知值；补读不运行内容解析。
6. 任一阶段取消／失败／盘离线，不清掉未确认删除的旧条目。新快照与游标的提交边界清楚，重启后不会将半成品当作完整快照。
7. schema 如需升级，增加迁移测试，兼容已有 schema 2；拒绝无关／较新数据库，不迁移 `index.db`。保留 128 位身份、事件去重、原子 checkpoint 的修复。
8. V4 当前不支持。至少保持检测到后不消费、不静默推进并补扫；如本轮实现支持，按微软文档解释 range tracking 含义并补边界测试，不能强行按 V2/V3 解码。
9. 默认按真实能力选择通道。缺权限时 UI 显示通用通道和原因；不能要求整个 GUI 管理员运行，也不能假报 native_ready。
10. F: 若当次允许，只读进行有界能力验证，报告统计，不导出整盘文件名。完整真实卷建库是单独可取消的验证项；未跑完整就写未验证。通用样本完整扫描和原生合成完整枚举均必须验证。

交付：原生建库实现、回退、真实／模拟分别记录的测试结果。通用回退可用不代表原生完整通道验收通过。

### C. 将目录检索接到“探索”（必须）

1. 搜索区域使用“探索／智答”模式。探索提供折叠内的检索范围：已选电脑位置、原资料库，或两者；保留旧版正文检索，不让接目录库后旧资料搜不到。
2. 目录搜索支持名称／路径、扩展名、来源／根目录、大小写、排序和分页。目录模式不把“仅有效文件／文号”等正文库专用条件悄悄套用成漏检。
3. 目录名称查询维持字面语义；现有资料库 AND／OR／NOT、同义词、错字容错、分类等语法保留。两种查询规则要在相应筛选／帮助内说明，不能悄悄改变原引擎。
4. 第一批结果尽快显示；结果有界、可继续加载。输入防抖、取消旧查询、请求版本校验，旧结果不能覆盖新输入。清空关键词、切范围、切模式都要失效旧请求。
5. 同一路径的目录命中和正文命中合并，保留命中依据。硬链接不同路径不误合并。目录名命中、路径命中、正文命中分清，尚未分析内容不能宣称语义命中。
6. 已入内容库文件继续使用原正文高亮／章节／页码预览。仅在目录库中的文档按需读取到受控预览／缓存，不能选一条结果就把整盘文件自动加入旧库。
7. 图片可使用现有 Qt 能力原图预览；未知格式或无法预览显示文件信息、原位置与打开动作。目录能进入或打开；离线、无权限、文件已更名／删除有明确提示。
8. 双击／打开原文件／打开所在位置／复制路径必须指向真实文件，目录索引路径不能被拼到 library 中。媒体与图片缩放不拉伸，关闭切换后释放资源。
9. 从目录结果加入资料库必须是明确操作，沿用原入库预检、复制／仅登记偏好和冲突处理，不在目录索引中发明另一套导入逻辑。
10. 缺少覆盖或扫描仍进行中时，空结果显示实际范围状态。不得把“目录尚未扫描／内容未分析”写成“电脑上没有这个文件”。

交付：真实 GUI 操作可走通样本目录发现→搜索→预览→打开→更名／删除后的结果更新。

### D. 极简界面与入口整理（必须）

#### 侧栏与搜索框

- 侧栏只留“搜索、资料库、收藏”三个文字导航，不加图标；底部“菜单”。去掉独立“镜仔智答”侧栏项。
- 第二列输入框左端紧凑切换“探索／智答”；探索执行按钮用真正的放大镜图标，位于输入行，不再保留占一整行的“搜索”大按钮。补 tooltip、无障碍名称和 Enter 行为，不用容易缺字的字体符号代替图标。
- “选项”改“筛选”，默认折叠，显示实际生效条件数。精确／模糊、格式、来源、大小写和高级字段在展开后出现；按模式隐藏不适用字段，避免误导。
- 常驻“相关程度”下拉移入“结果”菜单；保留原排序能力。目录结果只提供对其有意义的排序，正文结果保留原排序。
- 现有搜索历史／常用搜索／恢复阅读仍可找到。搜索范围管理置于范围控件，不再在侧栏、全局顶栏重复摆同一主按钮。

#### 结果与正文

- 结果仍在第二列，长命中片段可折叠／展开、键盘可访问；不能直接截掉后没有展开入口。正文区域保持通高。
- 正文顶部最多一条紧凑工具栏：文件名可省略显示并有完整提示；位置与阅读操作紧凑排列。取消大标题、重复文件名和空白副标题占行。
- 正文顶部“⋯”改为“阅读”，按复制、显示、跳转、当前文件分组；PDF 专用操作按条件出现。保留行／页跳转、章节、放大、原始 PDF、专注阅读、收藏和原文件定位。
- 不把文件大小、通道、开发状态等长信息常驻在正文上方；这些进入详情／范围面板。不能通过缩小字体到难读来腾空间。

#### 菜单归位

- 底部菜单按“任务、工具、设置、帮助”组织，退出单独分隔。任务显示目录／内容任务真实进度、取消和错误；工具按用途分组。
- 启动、热键、协议唤起归设置，避免再平铺全局一层。结果菜单只放当前结果的排序、查找／显示、导出、交给智答；阅读菜单只放当前阅读对象操作。
- 同一主入口唯一。允许结果上下文的“交给智答”动作和菜单内为保持旧功能保留的高级工作台，但要明确它们的作用，不再额外造一个重复首页导航。
- 生成完整入口迁移表：旧入口 → 新位置 → 原生／兼容 → 是否验证；旧使用说明中的功能一个不丢。

#### 清晰度与窗口

- 子窗口使用 Qt 高 DPI 策略与正常布局，不做位图放大。检查 100%／125%／150%／200% 下字体、图标、滚动和对话框边界；未能实机测试的档位写模拟／未测。
- 保持 Windows 原生窗口最小化／恢复动画，不重建窗口、不通过全黑蒙层逐块揭开。测试任务栏恢复、托盘唤起、关闭选择和多次切换，不让目录任务使主线程卡住。
- 检查最低窗口尺寸及常用分辨率；隐藏筛选后正文可见高度不低于现有版。提供实际截图与测量，不交纯效果图。

### E. 智答接入及既有能力保留（必须）

1. 模式切换到智答，主搜索区提供真实问题输入、资料范围／选中结果上下文、回答区和可回到右侧预览的来源。复用现有本机 `ai_qa.py`、模型设置和向量索引，不另建与搜索隔离的资料库。
2. 支持流式显示、停止、失败提示，明确“基于资料”与普通聊天。无本机服务／模型时说明缺少什么并提供原设置入口，不能伪造回答。
3. 未做内容分析的目录命中不能直接当作可靠资料依据；可按需分析支持格式后再问，或提示该资料尚未可用于回答。
4. 保留旧版完整模型设置／服务测试、索引管理、多轮历史、停止／重答、导出和来源能力。尚未原生迁移的复杂操作可经明确的“完整智答工作台”兼容入口保留，并在功能表标记；不能把弹出旧工作台作为主界面智答整合已经完成的唯一证据。
5. 单独测试资料来源不串到下一次查询；更名／删除／内容变化后缓存正确失效；取消旧回答后迟到 token 不写进新会话。测试用本机假服务或确定性响应，真实模型未就绪需如实记录。

### F. 多模态后续接入准备（本轮必须盘点和设计，实际能力单独验收）

目标最终包含“输入女孩抱着小狗，找到相关照片／视频／文档插图”。目录检索完成不能宣布此目标完成。

交付下一阶段可实施设计，至少写清：

1. 盘点现有正文／OCR／向量／本机服务能力及实际可用状态，区分独立图片、PDF／Office 插图、视频帧、音频转写；未安装不下载。
2. 统一文件身份、内容版本、页码／图序／时间点契约，订阅 catalog 真实内容变更的分析队列；更名不重算特征，内容变化重算，硬链接不重复算但路径保留。
3. 确定本地模型／推理候选的中文描述效果、许可证、模型大小、内存／显存、CPU 可行性和分发策略。结论有官方文档／论文依据及日期，不凭项目宣传给性能承诺。
4. 画面检索先接独立图片，再扩展文档内图、视频、音频。区分“画面出现”与“文字／语音提及”，相似度不冒充准确率。
5. 设计隔离验收集：女孩抱狗、女孩牵狗、女孩站狗旁、男孩抱狗、只有文字提及等。报告候选排序与误检／漏检，验证文件、页／帧定位和增量。
6. 本轮可把分析队列与能力状态接好，但不能仅因建了空表／按钮就写“支持多模态”；未完成能力不作为可用搜索方式对用户展示。

## 四、代码接入点

- `search_app/discovery/provider.py`：服务接口、通用扫描与日志交接、同步和有界实验。
- `search_app/discovery/catalog.py`／`schema.py`：目录查询、身份、事件、迁移与 checkpoint。
- `search_app/discovery/watch.py`：有界通知队列和 observer 生命周期，不调用旧正文 watcher。
- `search_app/qt_frontend/window.py`：窗口、搜索任务、结果选择、预览、退出。
- `search_app/qt_frontend/minimal_ui.py`：第二列搜索控件、正文工具栏和全局菜单。
- `search_app/qt_frontend/search_experience.py`／`result_snippets.py`：排序、结果分组／展开、原文预览。
- `search_app/qt_frontend/backend.py`：旧内容 Store、配置合并与预览。不要用 Store.scan 直接充当全盘目录扫描。
- `search_app/qt_frontend/jobs.py`：任务队列、取消、主线程回调；不要对同一来源并行写入。
- `search_app/qt_frontend/parity.py`／`legacy_bridge.py`／`tools.py`：完整兼容功能、模型设置、向量检索与智答复用。
- `search_app/qt_main.py`：单实例、生命周期和 `--data-dir`；验证工具必须显式隔离。

接口允许为正确性增补，但写版本与兼容说明，不修改调用约定却让旧测试绕开真实实现。

## 五、验收清单

下列测试必须使用新模块的真实调用链，不能全靠模拟 GUI 回调：

1. 现有 289 项基线继续通过；新加测试覆盖真实风险，不删原断言以凑通过。因用户已批准入口变化调整断言时写明原因与替代验证。
2. 中文、空格、引号、`% _ \\` 字面查询，路径边界，大小写，无扩展名，分页稳定且无重复／遗漏。
3. 多来源、重叠目录、硬链接多路径、重解析点循环、长路径、目录／文件更名、移入／移出、删除和内容修改。
4. 首次扫描期间变更与交接、扫描后持久监听、关闭后离线变更再启动、通知溢出和日志换代恢复；真实与注入分别写。
5. 取消、部分失败、权限不足、盘离线不得清旧索引；事件失败不得提前推进 checkpoint。重启／重复回放幂等。
6. 快速连续输入、切范围、切模式、清空查询、关闭窗口，迟到结果不覆盖新状态；任务进行时 UI 仍响应。
7. 样本文件从探索真实找到，正文／图片／PDF／未知格式预览行为可用；旧内容检索、收藏、入库、导出和完整智答入口仍可用。
8. 任务栏最小化／恢复至少 20 轮，包含正在建立目录时；检查是否有全黑区域逐块恢复。不能只证明窗口对象存在。
9. 至少 10 万合成目录记录复测：写入、库大小、查询首批、深分页、内存、取消；明确 OS 缓存与 Python 分配／进程工作集的区别。
10. 除合成测试外，生成真实目录样本做端到端增量。原生有权限时只读验证；权限缺失不能将模拟标记为真实。
11. 对候选 EXE 使用隔离数据验证单实例、任务、搜索、兼容工具和退出。记录构建源码与候选哈希；禁止覆盖正式版。
12. 结尾核对真实 EXE、index.db、配置和资料未变。记录开始与结束 git 状态，说明每个额外改动。

全量回归可用工程测试运行器：

```powershell
python search_app/tests/run_tests.py
```

若本机 Python 的 platform/WMI 查询卡住，复用 `qt_main.py` 已有 Win32 回退策略或上一轮 review-manifest 中的测试包装命令；不要因此把 discovery 真实文件系统／USN 调用一并 mock。

## 六、交付物与停点

在 `docs/discovery_integration/` 交付：

- `IMPLEMENTATION.md`：最终架构、接口、schema／迁移、监听／恢复和已完成事项。
- `FUNCTION_MAP.md`：所有旧功能与新入口映射，原生／兼容及验证状态。
- `VALIDATION.md`：精确命令、测试日志位置、真实／模拟／未运行、性能与截图。
- `MULTIMODAL_NEXT.md`：F 项设计和未就绪条件，不假报能力。
- `HANDOFF.md`：修改清单、启动方式、候选位置、缺口与 Codex 重点复核点。
- `handoff.json`：本轮最终文件 SHA-256／字节数、模块/API/schema 版本、测试计数、候选 EXE 与构建来源、保护哈希、真实／模拟／未完成标识。

保留 `docs/discovery_prework/` 的历史记录，不重写旧 handoff 假装它覆盖新代码。当前源码有新变化时以新 integration 清单为准。最终再算一次哈希，避免清单生成后继续改源码。

候选源码与 EXE 要能独立运行，提供清楚的隔离启动命令。若构建脚本原清单只记录 Qt 文件，本轮扩展到 discovery、入口和相关适配模块，确保能审计 EXE 来源。

完成后停止：不替换正式程序，不更改快捷方式，不开启真实全盘内容分析，不提交／发布。最终回报按“已实现、真实验证、仅模拟验证、未完成”分开；附失败日志和剩余问题，不只给通过数量。由 Codex 接手独立复核后，再决定正式接入与发布。
