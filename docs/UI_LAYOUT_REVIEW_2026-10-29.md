# 镜仔搜索：全入口画面与交互评审

日期：2026-10-29。评审对象：当前新版，以及从新版进入的完整兼容工具。

本次结论：主界面的紧凑方向适合继续保留；目前最大的短板是隐藏窗口之间不一致，以及界面没有清楚区分“正在看的旧资料”“本次检索结果”“本轮回答依据”和“失败提示”。优先解决这些问题，比继续更换装饰字体更有价值。

本轮只形成评审材料，没有修改正式程序、用户资料或系统设置。

## 检查方式与边界

先查看现有程序实际窗口，再使用当前代码在独立样本资料库中打开各入口。新版主页面、菜单与子菜单、右键、筛选下拉、阅读模式、PDF、图片、设置、导入状态、关闭确认，以及完整兼容工具均纳入检查。补查了手机服务实际启停与二维码生成、引用预警和合规扫描的标签页、版本选择及对比结果、内置同义词组、OCR 诊断和本地引用关系图。

最终目录记录 **119 个检查场景、260 张截图，按图像内容去重为 190 张画面**。这些数值包含菜单、下拉框、不同状态和重复采集，不代表 119 个独立窗口，也不代表所有功能都已通过验收。逐项入口、截图和菜单内容见 [覆盖清单](<D:/桌面/镜仔搜索/docs/UI_REVIEW_COVERAGE_2026-10-29.md>)。

以下情形特别区分：

- 多数复杂窗口使用真实组件和独立样本打开；为防止误写用户资料，部分系统文件选择器、通用输入框和确认框使用相同 Qt 组件重建并取消。不能用这些重建选择器的外观判断正式版 Windows 原生选择器的外观。正式 EXE 的软件打包保存窗口已另行实开核对。
- 智答 Markdown 排版使用固定样本流检查，没有把样本回答当作真实模型效果。连接失败状态使用隔离的无服务地址触发。
- 原位还原的最终确认使用模拟校验结果打开，随后取消；没有切换正式资料库。注册协议、开机启动没有实际写注册表。
- 完整智答的模型设置、测速、历史子窗在隔离兼容进程中出现隐藏或空白。模型设置另行展开查看；历史全文以调整定位方式的辅助场景查看。这些辅助画面不能算正常打开链路通过，正式安装包仍需复核该问题。
- 旧版库管理高级菜单已显示并记录；采集辅助进程退出不顺利，已结束该辅助进程，该场景不记为通过。
- 引用关系图已实际生成并由 Edge 渲染，未逐项验证所有图谱鼠标交互。意见反馈的外部网页、官网搜索结果、真实手机扫码后的完整手机页面、外部 Office/WPS 窗口没有冒充已体验。
- 本轮重点是当前机器 125% 缩放下的全入口视觉与交互检查，不是所有硬件、分辨率和数据规模的穷举验收。

## 体验评分

这是主观设计评审分，不是自动测试通过率。采用全窗口口径，不能直接沿用此前局部主界面的分数。

| 维度 | 权重 | 得分 | 扣分依据 |
|---|---:|---:|---|
| 主界面视觉与紧凑程度 | 25% | 8.2/10 | 已较克制，但智答层级重复，窄区域信息较拥挤 |
| 排版与信息层次 | 20% | 8.0/10 | 阅读区域清楚，部分表格、长表单和工具页仍需整理 |
| 操作可发现性 | 20% | 7.0/10 | 关键动作藏在菜单、双击和提示文字中 |
| 状态反馈与错误恢复 | 20% | 6.5/10 | 旧预览、失败文本、停止后的二维码容易造成误判 |
| 跨窗口一致性 | 15% | 7.5/10 | 中英文按钮、旧工具密度和子窗行为不统一 |

加权结果约 **7.5/10**。主界面外观单项已达到 8 分以上，全窗口体验仍被状态表达和隐藏窗口拖累。修复后应按同一套场景重新评分，再判断是否达到 9 分。

## 最先处理的 8 项

| 编号 | 优先级 | 观察到的问题 | 建议与验收标准 |
|---|---|---|---|
| A01 | P0：先复核阻断 | 隔离完整智答中，模型设置、测速、历史子窗存在已创建却未正常显示的情况，父窗又有遮罩 | 优先在正式 EXE 重现；统一父子窗口、定位和模态行为。子窗必须可见、可关闭；关闭后父窗立即恢复，不留遮罩。不能仅凭“窗口对象存在”判通过 |
| A02 | P1 | 智答提示“缺少正文依据”，右边仍显示先前打开的 PDF，容易被误认为本轮依据 | 保留阅读位置时明确标记“上次阅读，与本轮回答无关”；只有本轮真实引用才能标记“回答依据”。来源不足时给出“先搜索正文”“改用全库资料”入口 |
| A03 | P1 | 失败说明直接写进回答框，“复制回答”仍可用 | 错误使用独立状态区域；正常答案、部分生成、失败分别处理。纯失败时禁用复制回答；部分生成允许复制并明确未完成 |
| A04 | P1 | PDF 页码右侧的 ‹ › 实际用于上一处/下一处命中，视觉上像翻页 | 分开“第 7/120 页”和“第 3/12 处命中”两组控件，提示与键盘操作一致 |
| A05 | P1 | 开机启动处理逻辑还会启用手机服务，确认文字只提到开机启动 | 开机启动与手机访问分别保存、分别启停。只切换开机启动时，手机服务状态不得变化。此项由代码核对确认，未实际修改系统启动项 |
| A06 | P1 | 手机服务停止后，二维码、地址与复制入口仍保留 | 停止时清除或遮盖失效二维码，地址标记已失效，禁用复制；主按钮改为“启动手机访问”，服务运行时再显示“刷新配对码” |
| A07 | P1 | 任务详情显示 Python 字典或完整错误堆栈 | 首屏显示“处理成功 2 项、失败 1 项”“失败原因”“下一步”；程序堆栈放进可展开诊断区，提供复制诊断 |
| A08 | P1 | 入库的保留两份/替换/跳过藏在“双击更改”；完成后仍显示“开始入库” | 处理方式直接有下拉箭头；完成后主动作切换为“完成”，失败时提供“重试失败项”，避免用户猜测是否已经执行 |

P0 表示可能阻断使用、应先复核定位；P1 表示影响高频理解与操作；P2 表示体验精修。隔离环境复现的问题不直接等同于所有正式环境必现。

| G06 | P1 | 帮助、功能位置说明随实际入口同步，删除旧路径提示；点击说明可进入对应功能 | 例如范围已成为直接入口，就不能继续只指向旧的“筛选→范围管理”路径 |
| G07 | P2 | 工具中心说明写明用途及是否打开独立窗口，减少“完整工具/沿用旧版流程”这类实现描述 | 不熟悉版本历史的用户，也能选择需要的功能；旧版备用入口仍可保留 |
| G08 | P2 | 统一快捷键、Tab 顺序、默认按钮、Esc 关闭和焦点返回；窄滚动条扩大实际点击区 | 键盘可完成搜索、阅读、编辑与取消；关闭子窗后回到原控件，不跳到背景窗口 |

## 建议实施次序

第一批先解决 A01～A08：阻断、状态误导、隐含服务变化和恢复路径。每项都用同一场景复测，不能只看截图变好看。

第二批处理高频路径：范围与筛选、搜索结果辨识、阅读/PDF、智答宽度与来源、入库操作。保留目前紧凑控件和统一功能字体，避免反复放大再缩小。

第三批统一完整工具的窗口模板、表格、设置、帮助和诊断呈现。优先用统一组件修复共性，不同时重写所有旧工具。

建议最终验收使用当前资料与隔离样本两套路径，覆盖 100%/125%/150%/200% 缩放、亮暗主题、窄宽窗口，并复查菜单、键盘、长名称、空结果和失败状态。完成这些检查后再重新评分，不预先承诺未验证的分数。
