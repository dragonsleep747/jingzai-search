# Codex 独立复核、修订与交付

日期：2026-10-29。当前模块 **0.3.0 / catalog schema 2**。

## 结论与范围

这批 dsh 交付确实提供了可运行基础，但原先 305 项测试通过不足以证明实际流程正确。本次独立复跑基线、修订源码、补充回归，并验证了 Windows 实际卷、实际打包程序和旧资料库检索兼容性。

当前交付支持文件目录发现、可选范围、名称／路径探索、原资料库正文搜索、混合结果、按需预览、持续更新及新版智答入口。完整画面语义搜索、视频／音频内容索引和真实模型问答验收仍未完成。原有资料入库 OCR 能力保留，不把它称作全盘多模态索引已完成。

原始交接文档与 handoff.json 保留作历史记录；本次修订的最终文件、保护检查和程序来源以 **review-manifest.json** 为准。

## 独立发现并修复的问题

| 问题 | 修订结果 |
|---|---|
| 混合搜索把正文命中算入总数，却从结果列表移除 | 正文和目录结果共同呈现，同一路径合并，保留正文片段及来源 |
| “已选电脑位置”查询没有限制勾选来源，取消所有勾选仍搜全库 | 目录查询与已选来源取交集；空选择返回空结果；覆盖统计同样按选择计算 |
| 异步入口跨线程持有 RLock，后台扫描可能死锁 | 在锁内登记任务，由执行线程管理自身生命周期；重复请求合并，等待并发槽时也可取消 |
| Qt 任务未登记到控制层，“停止”无法终止实际扫描 | Jobs 取消与控制层令牌共同传播，范围面板连接实际任务 |
| 移除范围时，后台扫描可能继续写回条目 | 移除先取消并等待写入结束，期间拒绝新任务，再只移除索引 |
| 扫描之后没有持续监听，也没有实际定时同步 | 枚举前缓冲通知，结束后回放并持续监听；加入有界调度、失败退避和退出收尾 |
| 软件关闭期间的变更未对账，却显示完整 | 重启标记需要校验；已选范围可按偏好自动恢复；同一会话已在监听的不误标离线缺口 |
| 原生路径依赖根目录记录恰好被枚举到，卷根保存为 F: | 读取真实根身份，保存完整 F:\ 根路径，缺父路径按身份尝试恢复 |
| 硬链接多路径、系统子树和重解析点覆盖不足 | 实际硬链接名称枚举；目录／元数据排除规则及链接不递归；未确认完整时不清旧代次 |
| NTFS 内部 $Extend 缺父记录被当作普通资料孤儿 | 按 NTFS 保留元数据目录规则排除其子树；普通缺父记录仍要求校验／回退 |
| 原生提交阶段不及时响应取消；清旧记录与 checkpoint 分开 | 分批检查取消，发布完整代次与 checkpoint 同事务，错误回滚 |
| 临时路径库每个目录执行磁盘同步，真实建库很慢 | 只对可重建的私有暂存库关闭同步，正式 catalog 的事务与 checkpoint 规则保留 |
| 无变化轮询也把全部 FRN 路径加载进内存 | 延后到确有日志批次时才加载映射 |
| V4 能力与实际记录混同 | V2/V3 枚举可建立快照；日志按能力请求到 V4，遇到尚未消费的版本保留游标并补扫 |
| 查询跨范围／模式后，迟到结果与旧上下文可能混用 | 两类检索共用失效边界，取消所有旧请求，清空结果时清空智答依据 |
| 目录结果固定 100 条，没有继续入口 | 有界分页、继续加载与 has_more；已加载结果可导出 CSV，不冒充全量导出 |
| 默认混合范围丢失模糊、类型、高级字段及纯状态查询 | 正文侧保留原条件；目录侧使用自身条件；无正文关键词的元数据查询继续可用 |
| 仅目录模式的筛选计数包含没有生效的正文条件 | 隐藏不适用项，徽标按实际查询条件计算，清除条件涵盖新字段 |
| 结果菜单复用 QWidgetAction 导致排序控件随菜单销毁 | 使用独立菜单动作，原排序控件保留，反复打开可用 |
| 目录文件只显示属性，图片在 GUI 线程反复解码 | 受控按需文本／Office 预览、原始 PDF、后台图片读取与缓存缩放，不自动入库 |
| 新文件预览重复一条工具栏、旧文件名／动作残留 | 共用单条阅读栏，按阅读对象切换动作，保留通高正文 |
| 智答跳到独立整页，来源无法同屏阅读 | 智答放在第二列，问题与探索共用输入区，来源继续在右侧预览 |
| 迟到 token、问题输入防抖可能误发送 | 回答代次与取消检查；仅显式发送，支持资料问答与普通聊天 |
| Qt 池线程长期保留旧引擎只读连接，文件清理／切换仍占用库 | 每个任务在所属线程释放其只读连接缓存 |
| 帮助和位置说明仍引导去已删除的侧栏智答、“选项”及阅读“⋯” | 更新为探索／智答、筛选和阅读，完整工作台仍可达 |
| 构建工具可以给旧 EXE 重写成当前源码清单 | 拒绝 manifest-only 重新背书，要求实际构建后再记录来源 |

## 验证证据

所有本轮日志和样本在 `.tmp/integration-review/`。只用自行生成的文件做实际更名、删除、入库和系统打开验证；卷建库只读取元数据。

- 独立基线：305 项全部通过；修订后增加 34 项针对性回归，最终 **339 项全部通过，无跳过**。测试覆盖真实目录通知、取消、范围边界、分页、混合命中、状态筛选、原子发布、晚到结果／token 等。
- 真实 F: 完整尝试：读取 58,187 条原生记录，收录 58,168 条文件／目录条目，按规则排除 20 条并补真实根条目；失败 0。后续 USN 同步游标 29755936，无剩余积压／补扫标记。来源：native-real-fast.json。
- 本机 F: 对照：路径暂存同步优化前约 80.36 秒，优化后约 **8.50 秒**。这是当前卷、当前缓存与负载下的结果，不是百万文件或所有电脑的速度承诺。
- C:/D:/E: 实际当前权限下原生卷接口不可读，通用目录回退保留；未提权、安装服务或改写系统日志。
- 原生卷的取消也真实执行过：40 秒时停止，保留已写目录记录，未发布完整 checkpoint。unknown／V4、日志换代、回滚故障等主要为合成／注入验证，不写成真实日志恢复成功。
- 10 万合成记录复测：写入约 5.08 秒，66.20 MiB，Python 分配峰值 11.5 MiB，首次连接名称查询 16.42 ms、热平均 18.13 ms、offset=90000 约 110.66 ms；取消约 50.04 ms。OS 缓存未清，tracemalloc 不是进程工作集。
- 最终打包程序在实际桌面完成 **20 轮系统最小化／恢复、189 帧未遮挡画面采样，采样区域纯黑比例最大值为 0**，151 项检查通过；包含入库、章节、PDF、正文、收藏与阅读布局。统计见 release-native-window/result.json。采样不是全屏每个像素或所有显卡的保证。
- 实际打包程序通过 UI Automation 打开阅读菜单、执行原文件和所在位置动作；自建命令样本产生系统执行回执，资源管理器实际进入预期测试目录。测试生成窗口随后关闭。
- 实际候选第二实例搜索转发返回 0，主窗口未增加；范围对话框通过 UI Automation 读取 5 个实际来源；从应用菜单退出，进程结束。
- 现有真实内容库 193 份资料的四组查询与旧引擎分组／命中一致；保存、入库和 GUI 验收使用独立数据目录。
- **15 个完整兼容工具**的窗口启动、回调与实际 DPI 状态通过，最终程序记录在 compatibility-final/result.json。窗口能打开不等于外部服务功能已逐项验证。

## 原断言的审查

dsh 调整的侧栏、排序菜单和原生智答入口断言符合已批准的界面方向；只切到原资料库进行正文测试不足以覆盖默认混合模式，本次已补混合及纯元数据条件测试。智答从独立第六页进一步合并回搜索工作区后，页数回到五页，并增加智答／搜索共享页面的断言。帮助位置说明的旧断言也改为检查搜索输入区的智答入口，反向检查不再指向侧栏。

原生合成测试明确模拟根 ID 和元数据，不依赖 F: 上碰巧存在的真实文件。真实原生成功另由独立卷测试证明。

## 发布与资料保护

正式新版路径为 `镜仔搜索新版/镜仔搜索新版.exe`，与候选构建哈希对应。升级前整个程序目录保存在 `程序备份/` 下本轮唯一目录；原有“验收资料”附属目录也保留。

根目录旧版 `镜仔搜索.exe`、真实 index.db、config.json、config.qt.json 保持复核前 SHA-256。没有自动打开真实资料库运行验收、改变快捷方式或启动真实全盘正文／模型分析。正式新版程序的变化是预期发布变化，旧版程序哈希留在备份与发布回执中。

## 未完成与后续

1. 女孩抱狗等画面描述检索、文档内插图、视频帧／音频转写的统一内容队列尚未实现。目录名称检索不能代替这些能力。
2. 新版智答已接通本机服务调用和来源预览；流式／取消用确定性假服务验证。真实 Ollama 模型生成、联网服务、实际手机配对不在本轮成功声明内。
3. C:/D:/E: 的原生通道权限问题仍在，通用通道会对不可访问位置报告覆盖限制。V4 正文变更消费、真实日志重建与卷拔插恢复没有完整实机验收。
4. 本轮实际显示器为 125% DPI；兼容窗口验证了 DPI 感知和字号。其他缩放／显卡／多显示器实际体验仍应持续验收。
